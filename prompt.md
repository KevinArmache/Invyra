Voici une version plus claire, précise et exploitable comme brief pour une IA de développement :

### Création d’un nouveau modèle d’invitation

Je veux que tu crées **un nouveau modèle d’invitation électronique complet**, depuis **l’animation d’ouverture jusqu’à la dernière section de l’invitation**.

#### 1. Créer un concept réellement original

* Ne reprends pas un modèle déjà existant dans le projet.
* Ne te contente pas de modifier légèrement un modèle existant.
* Le résultat doit avoir **sa propre identité visuelle, son propre concept et ses propres animations**.
* Évite les layouts, transitions et compositions qui donnent l’impression d’être une copie d’un autre template.

#### 2. Proposer plusieurs directions créatives

Avant de coder, propose-moi **plusieurs concepts visuels distincts** parmi lesquels choisir.

Par exemple :

* une direction inspirée du mariage, mais avec une approche très cinématographique ;
* une direction élégante et artistique ;
* une direction immersive et expérimentale ;
* une direction totalement différente du mariage, applicable à d’autres événements : anniversaire, soirée, naissance, fiançailles, événement professionnel, etc.

Les propositions doivent surtout se différencier par **l’expérience d’ouverture, les transitions, la narration visuelle et les interactions**.

#### 3. S’inspirer du modèle « Éclat de mariage », sans le reproduire

Tu peux prendre **« Éclat de mariage » comme référence pour le niveau de finition et l’ambiance**, mais pas comme modèle à copier.

Je veux aller **beaucoup plus loin en matière d’effets et d’immersion** :

* ouverture spectaculaire ;
* transitions entre les différentes étapes ;
* animations liées au contenu ;
* effets de profondeur ;
* mouvements subtils ou cinématiques ;
* apparition progressive des informations ;
* interactions au scroll ;
* effets de lumière, particules, textures ou éléments graphiques lorsque cela sert réellement le concept ;
* transitions originales entre les sections ;
* conclusion mémorable.

L’objectif est que l'utilisateur ait l'impression de **vivre une petite expérience interactive**, et pas simplement de consulter une page web.

#### 4. Priorité absolue : l’effet « WOW »

Ne cherche pas uniquement à faire quelque chose de beau.

Chaque étape doit répondre à cette question :

> **« Est-ce que cette interaction peut provoquer un effet WOW chez la personne qui ouvre l’invitation ? »**

Je veux particulièrement travailler :

1. **L’ouverture de l’enveloppe / invitation**
2. **La révélation du contenu**
3. **Les transitions entre les sections**
4. **La présentation des noms, date et lieu**
5. **La galerie ou les éléments visuels**
6. **Le programme de l'événement**
7. **La confirmation RSVP**
8. **La conclusion de l’invitation**

Les effets doivent cependant rester **fluides, élégants et cohérents**. Évite d'ajouter des animations uniquement pour faire des animations.

#### 5. Penser au-delà du mariage

Même si le concept peut être présenté avec un exemple de mariage, je veux que tu réfléchisses à une architecture permettant éventuellement d’adapter le concept à plusieurs types d’événements :

* Mariage
* Fiançailles
* Anniversaire
* Baby shower
* Baptême
* Soirée
* Gala
* Événement professionnel
* Autres célébrations

Le concept doit donc être suffisamment fort pour exister **au-delà d'un simple template de mariage**.

#### 6. Contraintes techniques

Le modèle doit être réellement fonctionnel dans le système actuel.

* Respecte l'architecture existante du projet.
* Réutilise les composants et fonctionnalités existants lorsqu'ils sont nécessaires.
* N'introduis pas de dépendances inutiles.
* Le modèle doit être responsive : **mobile, tablette et desktop**.
* Les animations doivent rester performantes sur mobile.
* Prévois également les comportements liés au tactile et au scroll.
* Le contenu doit rester personnalisable à partir des données du template.
* Ne casse aucun autre modèle existant.

#### 7. Enregistrement en base de données

Une fois le modèle terminé et fonctionnel :

**enregistre-le directement dans le modèle `Template` de la base de données.**

Je veux donc un véritable template exploitable par l'application, et pas simplement une maquette ou une page de démonstration.

Vérifie notamment que :

* le template est correctement enregistré ;
* toutes les données nécessaires sont présentes ;
* il peut être récupéré par le système existant ;
* il peut être affiché comme les autres templates ;
* il ne modifie pas ou ne casse pas les templates existants.

### Objectif final

Je veux un modèle qui donne immédiatement l'impression :

**« Ce n'est pas une simple invitation web, c'est une expérience. »**

La priorité est donc :

**Originalité → Expérience d'ouverture → Effets WOW → Fluidité → Élégance → Réutilisabilité → Performance.**
